## How each patch works

### Hide profile header
- The logged-in home screen is a WebView showing moonsift.com (a React SPA). The header is web content, not native.
- Hook: index 0 of `LoggedInComposeables$CustomWebViewClient.onPageFinished(WebView, String)` →
  `ProfileHeaderPatch.onPageFinished(p1)`.
- The JS adds one `<style id="neil-morphe-hide-profile-heading">` to `<head>`, once:
  `.Profile-heading:has(~ .Profile-tabs){display:none !important;}`
  - `.Profile-heading`, `.Profile-tabs`, `.Profile-avatar` etc. are stable class names from the site's bundle
    (`https://www.moonsift.com/assets/index-*.js`). Both `Profile-heading` and `Profile-tabs` have styled-components
    rules, so they reach the DOM.
  - `.Profile-tabs` is only rendered on your own profile, so other people's profiles keep their header.
  - The style lives in `<head>`, so it survives SPA route changes. `onPageFinished` re-injects after full reloads.
- Possible issues to check on the device:
  - The header might flash briefly before `onPageFinished` fires.
  - If `:has()` isn't supported (WebView older than Chrome 105) nothing hides. Fallback: JS with a MutationObserver
    that sets `display:none` on `.Profile-heading` when `.Profile-tabs` exists.
  - If Neil also wants the "sustainability poll" (`.Profile-sustainabilityPoll`) hidden, add it to the same rule.

### Sanitize outbound links
How links leave the app (all confirmed in decompiled code):
1. WebView link → `CustomWebViewClient.shouldOverrideUrlLoading` (always returns true) →
   `LoggedInViewModel.onShouldOverrideUrlChange` → non-moonsift URLs → `UiEventEmitter.popup` → `MainContract.Label.Popup`
   → `MainActivity$bindLabels$1`: `startActivity(new Intent(ACTION_VIEW, Uri.parse(url)))`. **This is the product-link path.**
2. `AndroidMoonLauncher.launchCollection/launchMoonsiftUrl` → `new Intent(ACTION_VIEW, uri)`.
3. `TextComponents.HtmlText` link click → `CustomTabsIntent.launchUrl(context, uri)`.
4. `AddCollectionWebViewComposeables$CustomWebViewClient.shouldOverrideUrlLoading` returns false (loads in place).

Hooks:
- Every `Lcom/moonsift/...` method is scanned for `Landroid/content/Intent;-><init>(Ljava/lang/String;Landroid/net/Uri;)V`
  and `Landroidx/browser/customtabs/CustomTabsIntent;->launchUrl(Landroid/content/Context;Landroid/net/Uri;)V`.
  Before each call it inserts `invoke-static/range {vUri .. vUri}, SanitizeLinksPatch->sanitize(Uri)Uri` +
  `move-result-object vUri`. The Uri is the 3rd register (registerE / startRegister+2).
  This uses `addInstructionsAtControlFlowLabel` from `moonsift/shared/BytecodeUtils.kt`. Moonsift has its own copy
  on purpose: the Moonsift and theScore patches must stay independent, so nothing is shared between their packages.
  - Expected call sites, at least: `MainActivity$bindLabels$1` (Popup), `AndroidMoonLauncher` x2, `TextComponents`,
    plus any others in `MainActivity`. The patch throws if it hooks 0. Consider logging the count or asserting >= 4.
- Add-collection WebView: inserted at index 0 of its `shouldOverrideUrlLoading`. If `overrideUrlLoading(p1, p2)`
  returns true, it returns true (the extension already called `view.loadUrl(clean)`). Otherwise the original code runs.
  Only known redirector hosts are handled, which avoids redirect loops. Uses `v0` as a scratch register (the method
  has locals, so v0 is not a parameter register). Verify this once in the patched smali.

`LinkSanitizer` rules:
- Unwraps (up to 5 levels): `go.skimresources.com`, `go.redirectingat.com`, `redirect.viglink.com`,
  `redirect.sovrn.com`, `*.digidip.net/visit`, `click.linksynergy.com`, `*awin1.com`, `shareasale.com/r.cfm`,
  `l.facebook.com`, `lm.facebook.com`, `l.instagram.com`, `out.reddit.com`, `href.li`. Target param, in order of
  preference: `url, u, murl, ued, urllink, dest, destination`.
- Strips `utm_*`, click ids (gclid, fbclid, msclkid, …), affiliate params (irclickid, cjevent, ranMID, sscid, awc,
  xcust, sref, …). On Amazon hosts it also strips `tag`, `linkCode`, `ascsubtag`, `ref_`, `pd_rd_*`, `pf_rd_*`, etc.
  It keeps variant selectors such as `th`/`psc`.
- Never touches `moonsift.com` links (they carry the login `token` param). Never throws: on failure it returns the input.

JVM test used on the work PC (re-create it if needed; it is not committed):
compile `LinkSanitizer.java` with a small `main` that checks, for example:
`https://go.skimresources.com/?id=126855X1588436&url=https%3A%2F%2Fwww.crateandbarrel.ca%2Flakin-59-teak-bench%2Fs585400%3Futm_source%3DPinterest%26utm_medium%3Dorganic&sref=…`
→ `https://www.crateandbarrel.ca/lakin-59-teak-bench/s585400`. The VigLink, digidip, Amazon tag, fragment, nested
wrapper, moonsift, mailto and malformed cases all passed.
